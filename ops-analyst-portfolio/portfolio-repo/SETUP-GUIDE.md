# How to publish this portfolio on GitHub

## 1. Profile README (the front page of your GitHub)

1. Create a **new public repo named exactly like your username** (e.g. `jane-doe/jane-doe`).
   GitHub shows a hint: *"You found a secret!"* — that's the special profile repo.
2. Copy `profile-README.md` into it as `README.md`.
3. Replace every `<placeholder>`: your name, username, email, LinkedIn.

## 2. Portfolio repo

```bash
# from the extracted portfolio-repo/ folder
cd portfolio-repo
git init
git add .
git commit -m "Ops analyst portfolio: SLA analysis, KPI scorecard, report automation"

# create the GitHub repo and push
gh repo create ops-analyst-portfolio --public --source=. --push
#   or without gh: create the repo on github.com, then
#   git remote add origin git@github.com:Sasaki27/pilotproject.git && git push -u origin main
```

Then replace `Sasaki27` in both READMEs with your actual username
(`grep -rl 'Sasaki27' . | xargs sed -i 's/Sasaki27/YOUR_NAME/g'`).

## 3. Make it look real (30–60 min, highest ROI)

- **Screenshots beat code**: run each project, screenshot the chart/HTML output, drop the PNGs into each project folder and reference them in its README (`![MTTR trend](mttr_trend.png)` — `mttr_trend.png` is generated by project 1 already).
- **Pin the portfolio repo** on your profile (profile → "Customize your pins").
- Rewrite the headline results with YOUR real numbers from work — one true metric ("cut weekly reporting from 4h to 10min") outweighs three sample projects.
- Add a short "About this repo" line noting which parts are from real work vs. demo data.
